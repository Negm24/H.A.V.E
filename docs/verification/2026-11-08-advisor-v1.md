## Repeatable isolated browser acceptance

1. Run `docker compose exec -T -e ADVISOR_BROWSER_ACCEPTANCE=1 backend python
   manage.py test tools.advisor_browser_acceptance --noinput`. This explicitly
   creates a separate test database and waits four minutes after readiness.
2. In another terminal, run `docker compose exec -T -e BACKEND_ORIGIN=http://backend:8001
   kiosk pnpm --filter @have/advisor dev --port 5177`.
3. After readiness, copy `backend/media/advisor-browser/ready.local.json` to
   `development/advisor-browser.local.json`. Run `docker compose exec -T
   -e E2E_DOCKER=true -e E2E_BROWSER_CHANNEL=chromium -e E2E_ADVISOR_LIVE=true
   kiosk pnpm exec playwright test tests/advisor-live.spec.ts`.
4. Only if Playwright passes, write `{"status":"passed"}` to
   `backend/media/advisor-browser/result.local.json`. The server checks the
   final state and destroys the test database. Stop temporary Vite and remove
   the copied development ready file.

Do not use a normal management shell to run the fixture. Do not run concurrent
backend suites against the same test-database name, or concurrent Playwright
commands competing for the Docker TCP tunnels.

## Structured medication instructions - 8 November 2026

Implemented the user-approved progressive instruction editor. Doctors choose
structured directions, custom written instructions or explicit no instructions
recorded. Units are read-only and derived server-side from the stored catalogue
form through an explicit mapping (tablets, capsules, drops, mL, sprays,
applications and sachets). Unknown forms require custom directions; there is no
unit input, dose recommendation or automatic clinical calculation.

Schedules: specified daily Cairo times, hourly intervals, daily count, selected
meals, once only and as needed. Food relation is separate; as-needed use requires
a reason, minimum interval and maximum doses per 24 hours. Treatment duration is
separate from prescription validity. Only relevant fields appear; optional notes
are collapsed. One-off date/time uses the device timezone and is stored with an
explicit UTC offset. Review has a readable localized preview.

The backend validates schedule consistency, duplicate times/meals, positive
amounts, required duration and as-needed fields, and stale catalogue form where
provided. It derives bilingual directions and stores structured data plus unit
and text in the signed snapshot. Custom notes are not translated. Corrections
retain original signed content. Historical records retain their original text.
Bilingual structured PDF directions use compact spacing; a simple example fits
one page, with the final-page bottom-left signature verified in the rendered PDF.
